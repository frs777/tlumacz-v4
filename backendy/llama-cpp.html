BACKEND · LOKALNY

llama.cpp

Lokalny backend korzystający z zarządzanego llama-server. Obsługiwane są wszystkie modele LLM w formacie GGUF; program został szczególnie zoptymalizowany dla TranslateGemma.

KONFIGURACJA

Parametry backendu

Backend obsługuje konfigurację adresu i portu serwera, modelu GGUF, trybu obliczeń, równoległości, temperatury oraz szablonu czatu.

  • adres i port serwera
  • plik/model GGUF
  • CPU/GPU i tryb obliczeń
  • liczba równoległych zadań
  • timeout i parametry generowania
  • chat template
Zarządzanie procesem:
start → health-check → tłumaczenie → stop/restart.

Aplikacja może zarządzać własnym procesem llama-server, ale nie przejmuje kontroli nad obcym serwerem wskazanym przez użytkownika.

MODELE GGUF

GGUF i optymalizacja dla TranslateGemma

Tłumacz V4 może pracować ze wszystkimi modelami LLM dostępnymi w formacie GGUF. Szczególna optymalizacja dotyczy TranslateGemma, które korzysta ze specjalnego formatu szablonu translategemma i dedykowanego kontraktu żądania.

TRANSLATEGEMMA

Specjalny tryb llama.cpp

chat_template="translategemma" jest wariantem konfiguracji llama.cpp, a nie osobnym backendem. W tym trybie Lingua służy do detekcji języka źródłowego, a aplikacja buduje dedykowany prompt i korzysta z kontraktu /completions.

Standard

Standardowy llama.cpp korzysta z kontraktu /chat/completions.

TranslateGemma

Specjalny template przekazuje kody ISO 639-1 i metadane języków do modelu.

Lifecycle

GUI obsługuje start, stop, restart, health-check i kontrolę własności zarządzanego procesu.

Ważne: llama-server jest dodany do programu i instalowany razem z nim — nie jest zewnętrzną zależnością. Użytkownik zapewnia we własnym zakresie wybrany model GGUF. Zewnętrzną zależnością systemową dla Filter Engine pozostaje Java/Javac.
